## 导读：四个正面回答（给决策者的一页版）

**Q1：我到底需要的是什么？**

剥掉功能清单，真实需求是一句话：**"多人协作自测不可控，上线前我要知道每次改动该测什么、能快速测完、测了有记录。"** 拆成三层：① 管理诉求——改动的可见性与留痕（谁改了啥、影响谁、测没测，券商文化里这就是免责证据）；② 效率诉求——把 5 分钟的验证从 1 小时的启动仪式（起服务、连库、造数）中解放出来，这就是"免启动直测"的本质；③ 信任诉求——不信全自动，所以"系统建议、人拍板"。不是要做 MeterSphere 第二，是做一个**长在自己代码库上的、变更驱动的上线检查单**。

**Q2：这个想法可行吗？——可行，按确定性分档如下。**

| 档 | 环节 | 判断 |
|----|------|------|
| 很稳 | 动态表单、DB 直测+回滚、Git/SVN 感知留痕、LLM 配置+缓存、知识包迁移 | 全是确定性工程，M0 四个 PoC 已验证最难三块 |
| 能做但吃功夫 | 静态解析建"文件↔接口"映射、影响分析准确率 | 85% 可行，98% 靠长期打磨；"草稿人工确认"设计恰好消化了此风险（全方案最聪明的一笔） |
| 真硬骨头 | ① 验证码/SSO 自动登录；② 内网小模型抽取质量 | ① Cookie 接管兜底够用；② 是命门 → 学测分离主路 + 评测集门槛（§3.7） |
| 业界都没做到 | 影响分析零漏报 | 大厂精准测试靠插桩才敢承诺精度；我们不插桩，用"可解释证据+未测醒目"管理预期，**不对团队承诺 100%** |

最大敌人不是技术，是范围——所以 M2 硬验收定为真实项目端到端跑通（D4）。

**Q3：市面上有没有同类产品？——没有完全同型的，每个方向都有近亲。**

Apifox/Postman（知识靠人维护、不感知变更）、MeterSphere（人先写用例、系统只管执行，方向相反）、精准测试（**最像**，但靠覆盖率插桩重部署、大厂内部定制不外卖）、流量回放（思路可吸、形态不同）、AI 测试生成（2025-26 最热赛道，测"代码内部"，与我们互补）。核心组合"代码自学习 + 变更驱动选测 + 双引擎免启动 + 信创六库 + 学测分离"**国内外无现成品**；券商/信创环境正是"国外进不来、大厂方案太重、开源不支持达梦"的三不管地带——这就是身位。可融入项逐条见 §2。

**Q4：你自己（代理）加了什么想法？——最值钱的五个：**

1. **DB 回读断言（L4）**：接口写完同一用例内直查库验证落库真相，HTTP+DB 双引擎的组合拳，产品灵魂（§3.3）；
2. **信创六库一等公民 + DDL 回滚闸门**：MySQL/Oracle/TiDB 的 DDL 隐式提交会击穿"测完回滚"承诺，不设闸门一次直测能毁一套库（§3.1）；
3. **测试数据准备三件套**：读写标注/钩子/脏数据留痕，不补此坑 MVP 在真实项目撑不过两周（§3.2）;
4. **评测集**：把"内网小模型行不行"从信仰问题变成数字问题，推广信任凭证（§3.7）；
5. **起飞检查单**：版本区间→逐条改动测试状态→签字→导出"敢不敢起飞"结论单，名字、形态、留痕文化三者咬合（§4.1）。
另有：用例健康度自愈（§3.4）、失败转缺陷留痕（§3.5）、轻量 RBAC（§3.6）、"外网学内网用"升格核心工作流（§3.7）、市面功能借鉴清单（§2，本轮新增）。

## 1. 系统定位重述

**一句话**：PreFlight 是一个**变更驱动**的半自动测试系统——它学习代码库建立知识库，盯住每次提交，回答"这次改动该测什么"，把测法建议（直测/远程测）与候选用例摆到人面前，人拍板执行，结果与经验沉淀回知识库。

**它是什么、不是什么**（对照调研结论）：

| 品类 | 代表产品 | 它们的做法 | PreFlight 的差异 |
|------|---------|-----------|-----------------|
| 接口调试协作 | Apifox / Postman / YApi | 接口文档+调试+Mock，知识**靠人手工维护** | 知识从代码**自动学习**产生；测试范围由 **diff 驱动**而不是人挑 |
| 测试管理平台 | [MeterSphere](https://metersphere.io/)、TestWise、Runner | 人先写好用例，再自动化执行、管理缺陷 | 用例主要由系统**从变更生成建议**；定位是"上线前检查单"而非全流程管理 |
| 精准测试 | 腾讯知深、百度/京东内部平台 | 覆盖率**插桩 Agent** 建立代码↔接口映射 | **免插桩**（文件映射表），接入零侵入、适配内网快速落地；代价是精度略低，用"人工确认+可解释证据"补偿；覆盖率增强留作远期 |
| 流量录制回放 | [阿里 jvm-sandbox-repeater](https://github.com/alibaba/jvm-sandbox-repeater)、[货拉拉](https://testerhome.com/topics/40121)、[vivo](https://www.cnblogs.com/vivotech/p/15895164.html) | 录制真实流量当用例，回放并 diff 响应 | 不需要在应用内装 Agent；借鉴其"真实请求当用例来源"（HAR 导入，§4.3）与"响应对比"思想（基线 diff，§2.4） |
| AI 单测/回归生成 | [Diffblue Cover](https://www.diffblue.com/resources/uplift-java-test-coverage-out-of-the-box/)、[Code Intelligence](https://testguild.com/7-innovative-ai-test-automation-tools-future-third-wave/)、[TestCopilot](https://testcopilot.com.cn/)、[腾讯 TestMate](https://tds.qq.com/testmate/) | 从代码自动生成/维护单元级回归，主打用例自愈 | 它们测"代码内部"，PreFlight 测"改动对外影响"（接口+SQL 黑盒层）；**借鉴其用例自愈与变更跟随**（§3.4） |

**方向外部印证**：Google 的 changes-based test selection（[智能选测实践综述](https://juejin.cn/post/7472193292206768166)）证明"只跑受影响的测试"用**确定性工程**而非 AI 猜测是业界正道——与 v0.2"影响分析走文件映射、不靠 LLM 猜"的核心决策一致，保留不动。

## 2. 市面产品功能借鉴清单（融什么、怎么融、坚决不融什么）

总原则：**只融"纯工程、强化变更驱动闭环"的能力；不融"把 PreFlight 变成测试管理平台"的能力**——缺陷工作流、多租户、重型场景编排是 MeterSphere 们的战场，不是我们的。每项给出落点模块/里程碑与采纳裁决（①=一期融入，②=二期候选，✗=不做）。

### 2.1 来自 Apifox / Postman / YApi（接口调试协作）

| 借鉴点 | 怎么融进 PreFlight | 裁决 |
|--------|-------------------|------|
| 执行记录即"历史参数"：测过的请求自动成为下次快选 | 测试台参数表单加"最近使用参数"下拉（数据现成：`test_runs.request_snapshot`），零新模块 | ① M2（小项） |
| 一键生成 cURL / 代码片段 | HTTP 执行器把已组装请求导出 cURL，便于贴给开发排查（免截图） | ① M2（小项） |
| Postman Collection 双向格式 | §4.3 导入通道已定；顺带支持**导出**为 Collection，让团队存量资产双向流动、降低迁移心理门槛 | ① 导入 M2~M4（已列）/ 导出 ② |
| 接口的"多个示例"组织方式（一接口挂 N 组示例请求+期望响应） | 概念与我们的"用例=接口的参数化实例"同构，UI 上把用例列表做成"示例"心智（开发一看就懂） | ① M2 纯 UI 层面 |
| 内置 Mock Server（YApi 主打） | 已有规划：Mock 回放器（02 文档 §3.8.3），面向"离线验证请求构造"而非"前后端并行开发"，维持二期 | ② |
| 环境变量 `{{var}}` 高亮补全的交互 | 02 文档已含占位符机制，编辑器体验向 Apifox 对齐即可，不加功能只抄手感 | ① M2 顺手 |

### 2.2 来自 MeterSphere / TestWise / Runner（测试管理平台）

| 借鉴点 | 怎么融进 PreFlight | 裁决 |
|--------|-------------------|------|

## 3. 七项缺口补强设计

### 3.1 六库方言矩阵（D2 落地）

v0.2 驱动清单只有 MySQL/PG/MSSQL/Oracle，按 D2 扩展为六库。**关键认知：PreFlight 不重写业务 SQL**——直测执行的是从 mapper XML/注解原样还原的模板，方言差异由项目代码本身决定（代码怎么写、库上就怎么跑）。因此"方言支持"的真正含义是：**驱动接入、元数据获取、事务/DDL 行为、直测保护策略**四件事按库各自成立。

| 库 | 驱动 | 元数据来源（表/列注释、签名） | 事务回滚保护 | 直测注意事项 |
|----|------|------------------------------|-------------|--------------|
| 达梦 DM8 | `dm.jdbc.driver.DmDriver`（DmJdbcDriver18，**不在中央仓库，放部署包 `lib/`**） | Oracle 风格字典：`ALL_TAB_COMMENTS / ALL_COL_COMMENTS / ALL_TAB_COLUMNS / ALL_ARGUMENTS`；部分场景标准 `DatabaseMetaData` 亦可用 | DML 可回滚；**DDL 大概率隐式提交（兼容 Oracle），需 M3 实测确认** | 常见 Oracle 兼容模式；MyBatis 项目多经 `databaseId` 区分，见 §3.1.1 |
| Gauss | 需确认变体（见 §8-Q1）：openGauss/GaussDB 用 `org.opengauss.Driver`（Maven 中央有）；GaussDB(for MySQL) 走 MySQL 协议 | PG 系：`information_schema` + `pg_description` | **PG 系支持事务化 DDL（可回滚）**，是六库中最利于直测的 | URL/参数与标准 PG 有差异；`FETCH FIRST` 方言 |
| MySQL 5.7/8 | `mysql-connector-j` | `information_schema.TABLES/COLUMNS/ROUTINES`（TABLE_COMMENT、COLUMN_COMMENT 齐全） | InnoDB DML 可回滚；**DDL 隐式提交不可回滚** | `CALL` 存储过程可用 |
| Oracle | `ojdbc11`（按需 `lib/`，注意商用 license 提示） | `ALL_*` 字典视图 + `DatabaseMetaData` | DML 可回滚；**DDL 隐式提交** | 分页 `ROWNUM` 方言；连接串 SID/ServiceName 两种形态 |
| TiDB | 复用 `mysql-connector-j` | `information_schema`（大部分兼容） | DML 事务正常；**DDL 隐式提交** | **存储过程长期不支持/仅新版本有限支持**：TiDB 环境的"SQL 类改动"以表/查询为主，proc 直测在此库自然置灰并在页面说明原因；无外键，涉及引用完整性的断言走 DB 回读 |
| SQL Server | `mssql-jdbc` | `INFORMATION_SCHEMA` + `sys.extended_properties`（MS_Description 存注释） | **DML 与 DDL 均可回滚**（事务化 DDL） | 分页 `TOP/OFFSET-FETCH`；`EXEC` proc 直测可用 |

**直测统一规约按库收紧**：DDL 类语句在"不可回滚库"（MySQL/Oracle/TiDB/DM8-待实测）上**禁止走"提交"通道，除非环境被显式标记为可弃库/schema**（如独立的测试 schema）。这是防"一次直测毁掉一套库"的第一道闸。

**§3.1.1 MyBatis `databaseId` 多版本识别（新增能力）**：多库兼容项目（回访平台这类）常为同一 statement 维护多个 `databaseId` 版本。适配器需提取 `databaseId` 属性，接口卡/数据对象卡记录多版本 SQL 模板；直测时**按目标环境的库类型自动选择对应版本**，无匹配版本则提示降级。此项 M1 做提取、M3 做选择执行。

**落地方式**：M0 增加 PoC-E"六库连通与行为体检"——对每个可拿到的实例跑固定体检脚本（驱动加载、元数据拉取、事务回滚、DDL 行为、proc 调用），产出《库行为矩阵实测表》进知识库 artifacts，后续直测策略查表执行。拿不到的库（如暂无 TiDB 实例）先按上表理论值标注"未验证"，接入时补测。

### 3.2 测试数据准备（v0.2 最大盲区）

HTTP 远程测的写接口产生脏数据、且多数接口**依赖前置数据才测得到业务分支**。补三层机制：

1. **读写属性自动标注（M2）**：学习阶段由接口关联的 SQL 语句类型静态判定 `access: read | write | mixed`，写入接口卡。改动流/测试台醒目展示"写"标；直测建议规则升级——read 接口优先 HTTP 远程测，write 接口优先"直测+回读"或带钩子执行。
2. **执行前/后置钩子（M2，轻量）**：环境+接口级可配置 `pre_sql[] / post_sql[]`（如 pre：确保存在一条 status=0 的回访任务；post：删除本次造的数据）。**钩子 SQL 独立连接、显式提交执行**（与主测试的回滚保护分离），post 钩子默认自动跟随执行，页面上可视化"造了什么、清了什么的"清单。钩子本身走同一套参数绑定与黑名单规约。
3. **脏数据留痕（M2）**：`test_runs` 增加 `writes_expected: bool`（来自接口卡 access 判定）；写接口且未配 post 清理钩子的执行，结果区自动打"可能产生脏数据"标，报告与审计可追溯。

基础数据**快照/还原**（备份-恢复级别的数据管理）本期不做，列入 §7 演进——钩子机制已能覆盖小组级试点需求。

### 3.3 断言分层模型（把双引擎优势变成产品能力）

v0.2 的 `expect` 只有一个可人工补充的字段，太薄。`test_cases` 的期望改为**结构化断言数组**，分层可选（默认 L1 自动生成，L2~L4 由 LLM 给草稿、人确认）：

| 层 | 断言类型 | 示例 | 依赖引擎 |
|----|---------|------|---------|
| L1 | 状态码/耗时/异常 | `status == 200 && latency < 3000ms` | HTTP |
| L2 | JSONPath 等值/包含/正则 | `$.data.list[0].visitStatus == 1` | HTTP |
| L3 | 响应 JSON Schema 校验 | 响应结构 vs 接口卡出参 schema | HTTP |
| L4 | **DB 回读断言** | 调"提交回访"接口后执行 `SELECT status FROM t_visit WHERE id={{ret.data.id}}`（回滚方式读）→ `status == 2` | **HTTP + DB 组合** |

**L4 是 PreFlight 独有的组合拳**：接口改完没改坏数据库真相，一条用例内闭环验证，无需人再去手工连库查。实现上 L4 断言复用 DB 执行器（参数绑定、只读、回滚），断言上下文可引用前序响应字段（`{{ret.xxx}}`），天然支持"接口返回的 id 回查落库行"。存储过程直测同理：出参断言 + 回读断言。

`test_runs` 记录逐条断言的 pass/fail 明细；任一断言 fail 即 run fail。

### 3.4 用例健康度与自愈

接口卡（`interfaces`）增加 `schema_hash`（params_schema 规范化哈希）与 `version` 自增。用例（`test_cases`）记录来源接口的 `base_schema_hash`，新增 `health: active | suspect | deprecated`。

流程（M2）：增量学习导致接口 schema 变化 → 关联用例 `health=suspect` → 用例生成器对 suspect 用例产出**修复草稿**（旧参数 → 新参数的映射建议，走 LLM，离线环境给结构化提示"字段 X 已删除/Y 已新增"）→ 人确认后置回 active。改动流与用例库页面按 suspect 过滤提醒。

价值：回归用例库随迭代持续可用，避免"三个月后没人敢用旧用例"的测试资产通病。

### 3.5 失败 → 缺陷留痕闭环

执行失败不应止步于一条 run 记录。新增 `findings` 表（M2 轻量版）：

```
findings: id, project_id, run_id, commit_id(可空), file_change_id(可空),
          title(默认取用例名), severity, status(open/confirmed/false_alarm/fixed),
          noted_by, created_at
```

测试台失败结果区提供"转缺陷留痕"一键按钮，自动附上：触发改动链接 + diff 摘要 + 请求/响应快照 + 断言明细。价值有二：① 质量看板的"发现问题数/拦截率"（03 文档 §6 指标）从此有了可靠数据源；② 券商场景下"上线前拦截了什么"有据可查，是系统向上汇报的弹药。

### 3.6 轻量 RBAC（D1 落地）

单实例多人共用后必须区分"谁能干什么"。三角色本地账号（BCrypt 口令哈希 + 会话 Cookie，不接 SSO，列 §7 演进）：

| 能力 | 管理员 admin | 测试 tester | 只读 viewer |
|------|:---:|:---:|:---:|
| 项目/仓库/环境/凭据/LLM 配置 | ✓ | 查看 | 查看(掩码) |
| 触发学习、确认/编辑知识（接口卡、登录流） | ✓ | ✓ | ✗ |
| 执行测试（含 DB 直测回滚模式） | ✓ | ✓ | ✗ |
| DB 直测"提交"勾选、DDL 类直测 | ✓ | ✗ | ✗ |
| 标记测试状态、转缺陷留痕 | ✓ | ✓ | ✗ |
| 导出知识包（含凭据勾选） | ✓ | ✗ | ✗ |
| 用户管理、审计查看 | ✓ | ✗ | ✗ |

审计日志的 `actor` 字段由会话注入，不再允许前端自报。默认创建的第一个账号即 admin。

### 3.7 "学测分离"升格为核心工作流 + 质量评测集（D3 落地）

内网为主意味着：**高质量的云模型学习发生在网外，执行与留存在网内**。把 01 文档"场景 E"升级为标准工作流：

```
[网外合规机] 学习项目 + LLM 提炼 + 生成用例模板 → 质量评测达标
      → 导出知识包(zip) ──物理摆渡──▶ [内网机] 导入 → 感知-SVN/Git 同步照常
      → 改动流(降级摘要) + 动态表单 + HTTP/DB 执行 + 模板用例 全部在线
```

配套两件事：

1. **知识包增加"新鲜度契约"**：包内记录 `covered_revision`（知识覆盖到的代码版本）与学习时的 LLM 供应商/提示词版本。内网端同步到新提交后，若增量学习不可用（无 LLM），改动卡片明确标注"知识基线截至 rN，本改动未深度归纳"——宁可示弱，不可假装。
2. **评测集（extract benchmark，M1 落地）**：人工标注 20~50 个真实接口卡作为黄金基线（存 `artifacts/benchmark/`，随知识包迁移）。每次更换模型、修改提示词，先跑评测：输出 path/method/参数/表引用的字段级 精确率/召回率 对比报告。**没有评测集，离线小模型的抽取质量就是不可知论**；这也是试点后向"小组/更大范围"推广时的信任凭证。内网兜底小模型（Ollama）的可用性以评测集分数为准入门槛（建议 ≥85% 字段召回才允许在内网做自动草稿入库，否则只做降级摘要）。

## 4. 三个差异化亮点（别处没有、且贴合你的环境）

### 4.1 起飞检查单（Release Checklist）——名字与形态咬合

发布前选定一个**发布范围**（如 SVN r120→r135 / Git tag 区间），系统生成交互式检查单：

```
☑ 每条改动：影响接口 → 是否已测(test_status) → 最近执行结果(断言明细)
☑ 未测项高亮，须逐个"签字跳过"（填理由，留审计）
☑ 失败改动须关联 findings 且状态为 fixed/confirmed 才可勾选"已处理"
☑ 一键导出 HTML 报告（打印即 PDF）：改动清单、测试证据、签字记录、风险项
```

新增表 `release_checklists`（范围、生成快照、签字记录）。M5 落地，放"增值"最后一期但**数据模型 M1 就预留**（commits/file_changes/test_runs 已可支撑）。这是 PreFlight 区别于一切"测试工具"的流程卡点形态：它输出的不是测试报告，是**"敢不敢起飞"的结论单**——高度贴合券商留痕文化。

### 4.2 真实库元数据反哺表单与用例

学习阶段直连目标库拉取**真实**表/列元数据（注释、类型、长度、可空、默认值、枚举字典），与代码侧静态解析合并：

- 动态表单：参数自动带类型长度与中文注释占位、必填/默认值（把"猜的参数"变成"库保证的参数"）；
- 用例生成：`VARCHAR(64)` 自动生成超长串、可空列自动生成 null 用例、字典列从注释提取枚举值做边界；
- 展示：接口卡的 `db_objects` 悬浮即见列注释——测试员不用再去翻数据字典。

（这正是一向"直连达梦拉真实元数据"做法的产品化，M1 随适配器落地，六库元数据查询见 §3.1 表。）

### 4.3 存量资产导入冷启动

三条导入通道，降低首跑门槛、补充真实参数来源：

1. **OpenAPI/Swagger JSON**（M1）：直接生成接口卡草稿（`origin: import`，跳过 LLM 仍可用）；
2. **Postman/Apifox 集合导出**（M2）：请求+示例参数转用例草稿；
3. **HAR 文件**（浏览器 DevTools 导出的真实操作流量，M4）：过滤出目标域请求 → 生成"真实参数用例"候选，人勾选入库。流量回放系证明真实请求的测试价值远高于凭空造参。

## 9. 结论

v0.2 方案的骨架（变更驱动闭环、静态解析打底、LLM 只做归纳、一切落盘可迁移）经与五类同类系统对照后**全部成立，不需要推翻**。本文补的是三类内容：
