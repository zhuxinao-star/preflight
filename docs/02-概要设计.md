## 1. 总体架构

**单体服务**：一个 Spring Boot fat jar 承载 REST、前端静态资源、定时任务与后台线程池，**不使用 Docker**，以自包含部署包 + 启停脚本交付。

```
┌────────────────────────────────────────────────────────────────────┐
│                        Web 前端（Vue 3 + TS）                       │
│  项目管理 │ 改动流 │ 接口测试台(动态表单) │ 知识库浏览 │ 看板 │ 设置   │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ REST + SSE(任务进度/测试结果)
┌──────────────────────────────┴─────────────────────────────────────┐
│          应用服务 · Spring Boot 单体（Java 21 · 单 fat jar）          │
│                                                                    │
│  ┌────────────┐  ┌──────────────────────┐  ┌────────────────────┐  │
│  │ 仓库与变更   │  │ 知识引擎              │  │ 用例与执行引擎       │  │
│  │ · JGit轮询  │→ │ · 扫描/解析(适配器)    │→ │ · 用例生成          │  │
│  │ · diff解析  │  │ · LLM提取流水线       │  │ · HTTP执行器        │  │
│  │ · 改动分类   │  │ · 影响分析(文件映射)   │  │ · DB执行器(直测)     │  │
│  │ · 风险分级   │  │ · Lucene检索(BM25)   │  │ · Mock回放器        │  │
│  └────────────┘  └──────────────────────┘  └────────────────────┘  │
│                                                                    │
│  ┌────────────────────┐  ┌───────────────────────────────────┐    │
│  │ 认证与会话管理       │  │ LLM 网关                           │    │
│  │ · 登录流执行        │  │ · 多供应商/按用途路由 · 重试降级     │    │
│  │ · Token/Cookie注入 │  │ · 请求指纹缓存 · 用量统计           │    │
│  └────────────────────┘  └───────────────────────────────────┘    │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────┐     │
│  │ 基础设施：@Scheduled+任务表 │ 凭据加密 │ 审计日志 │ 导出导入  │     │
│  └──────────────────────────────────────────────────────────┘     │
└────────┬──────────────────┬───────────────────┬────────────────────┘
         │                  │                   │
   ┌─────┴─────┐     ┌──────┴──────┐     ┌──────┴─────────────────┐
   │ Git 仓库   │     │ 系统知识库    │     │ 外部目标                │
   │ 前端/后台/  │     │ SQLite(元数据)│     │ · 目标数据库(直测)       │
   │ 数据库目录  │     │ 文件(知识产物) │     │ · 被测服务(HTTP)        │
   └───────────┘     │ +本地索引    │     │ · LLM API(可本地Ollama) │
                     └─────────────┘     └────────────────────────┘
```

设计要点：

1. **两条确定性主线**：影响分析走"文件映射表"（学习期建立的源文件↔接口归属关系），请求执行走确定性引擎（HTTP/DB），LLM 只出现在"归纳与生成"环节——保证核心链路可离线、可靠。
2. **单体进程承载全部能力**：无需消息中间件，后台任务以数据库任务表驱动（幂等、可重试、单实例单写者）。
3. **一切落盘**：元数据进 SQLite，大文本（摘要、diff、LLM 输出）以文件形式存于知识目录并与元数据表关联，检索索引用本地文件型库（Lucene，M4 可选加向量索引）。整个知识库目录可 zip 打包迁移。

## 2. 技术选型（定稿）

> 工具链统一使用工作区 `tools/` 目录内的 JDK 21 与 Maven 3.9.11（已验证可用，Maven 走华为云镜像）。所有构建/启动脚本在**进程级**指定 `JAVA_HOME`，不修改开发机与目标机的任何系统环境变量。

| 层 | 选型 | 理由 |
|----|------|------|
| 运行时 | JDK 21（Temurin 21.0.12 LTS，`tools/` 提供） | 用户已备、LTS；部署包同样自带便携 JRE |
| 后端框架 | Spring Boot 3.5.x（Spring MVC，不用 WebFlux） | 生态成熟、内嵌 Tomcat、单 jar 部署 |
| 构建 | Maven 3.9.11（`tools/`，含华为云镜像 settings.xml） | 与 JDK 配套，公司内常见、易维护 |
| 语言 | Java 21（record、text block 按需使用） | 与运行时一致 |
| 自身存储 | SQLite（sqlite-jdbc）+ Spring JDBC（JdbcTemplate）+ Flyway 管理版本化建表 | 零运维、单文件、随知识包迁移；JdbcTemplate 天然 PreparedStatement 参数绑定 |
| 目标库驱动 | mysql-connector-j、postgresql、mssql-jdbc 内置；Oracle ojdbc 按需放入 `lib/` | DB 直测多类型数据库 |
| SQL 解析 | JSqlParser | 解析 SQL、提取表名与参数，配合 JDBC DatabaseMetaData 提取存储过程签名 |
| Java 源解析 | JavaParser | 抽取 Spring Controller/Service/Mapper 结构与注解 |
| Git | JGit 6.x（纯 Java） | fetch / log / diff 全内置，**开发机与目标机均无需安装 git 命令** |
| 检索 | Lucene 9 + SmartChineseAnalyzer（BM25 全文检索）；M4 起可选 DJL + ONNX Runtime 本地推理 bge-small-zh 向量（小规模语料内存暴力余弦即可） | 全本地、可离线；项目级语料规模（万级以下分块）够用 |
| LLM 接入 | Spring RestClient 直连 OpenAI 兼容协议 + Ollama | 统一网关、缓存、降级；主流供应商全兼容 |
| 调度 | Spring `@Scheduled` + 数据库任务表 | 单体内置，无需 MQ；任务幂等可重试 |
| 前端 | Vue 3 + Vite + Element Plus + axios + **自研 JSON Schema 表单渲染器**（递归组件，覆盖 string/number/boolean/enum/array/object） | 动态测试页的核心；构建产物打进 jar 的 static 目录，**运行期无 Node 依赖** |
| 加密 | JDK JCA（AES-GCM） | 凭据保险库，主口令不入库 |
| 日志/测试 | Logback / JUnit 5 | 标准组合 |

工程约定：groupId 暂用 `com.preflight`（上线前可改为公司域名倒写），主应用 `preflight-server`，前端源码 `preflight-ui`。

## 3. 模块设计

### 3.1 项目与仓库管理

- **职责**：项目 CRUD；一个项目下挂多个仓库条目，仓库分类型 `frontend / backend / database`；**VCS 类型 `git / svn` 二选一**，可填远程地址（自动拉取更新）或仅填本地目录（仅监听）。
- **关键点**：
  - 同步任务按 `vcs_type` 路由到对应客户端（见 3.6），把远程更新拉到本地工作副本后做提交比对；
  - Git 凭据 / SVN 账号密码存入凭据保险库（AES-GCM）；
  - webhook 接收端预留接口（Git 场景可免轮询）。

### 3.2 扫描与解析引擎（适配器模式）

- **职责**：遍历仓库文件 → 语言/框架识别 → 交给对应**解析适配器**产出结构化中间产物。
- **适配器接口**（核心抽象）：

```java
public interface LanguageAdapter {
    boolean match(Path file);
    List<ExtractedUnit> extract(Path file) throws Exception;
}
// ExtractedUnit: {kind: HTTP_ENDPOINT|SQL_STATEMENT|PROC_CALL|DDL|FE_API_CALL,
//                 name, signature, paramsSchema, sourceFile, lineRange, rawSnippet}
```

- **一期适配器优先级**（按国内后台技术栈常见度排序）：
  1. Java：Spring MVC/WebFlux Controller（`@RequestMapping` 等，JavaParser）+ MyBatis mapper XML / 注解 SQL（DOM 解析，JSqlParser 校验）
  2. SQL：`CREATE TABLE/VIEW/PROCEDURE/FUNCTION` 解析（JSqlParser）；存储过程签名可由 JDBC `DatabaseMetaData.getProcedureColumns` 动态兜底
  3. Node.js：Express/Koa/Nest 路由声明（规则 + LLM 兜底）
  4. Python：Django/FastAPI 路由（规则 + LLM 兜底）
  5. 前端：axios/fetch 调用清单、路由表（用于交叉印证，不产出接口卡）
- 未识别语言/框架的文件仍进入 LLM 通读兜底通道（成本更高，仅对无适配器覆盖的部分使用）。

### 3.3 LLM 网关

- **职责**：统一 LLM 调用入口；多供应商配置；**按用途路由**（`purpose: summary | testcase | extract | chat` 各自可指定不同供应商/模型）；请求指纹缓存；重试与供应商级降级；Token 用量统计。
- **缓存**：`(purpose, model, messages哈希, 关键参数)` → 响应。命中即回，不出网。这是能力 6 的关键组件。
- **提示词模板**：集中管理、版本化（存文件，随知识包迁移），保证同版本系统行为可复现。

### 3.4 知识提取流水线

- **全量学习**：目录扫描 → 适配器抽取 → 相邻文件聚合（Controller+Service+Mapper 归组）→ LLM 逐组提炼**接口卡**与模块摘要 → 草稿入库 → 人工确认。
- **增量学习**：只处理变更文件及其聚合组，合并策略为"文件级重提 + 实体级覆盖，人工编辑过的字段不被覆盖"（编辑保护标记）。
- **接口卡（InterfaceCard）核心字段**：

```json
{
  "protocol": "http",
  "name": "创建订单",
  "method": "POST",
  "path": "/api/orders",
  "params_schema": {
    "type": "object",
    "properties": {
      "skuId": {"type": "integer", "desc": "商品ID", "required": true},
      "count":  {"type": "integer", "minimum": 1}
    }
  },
  "auth": {"type": "bearer", "login_flow": "默认登录"},
  "source": [{"file": "OrderController.java", "lines": "45-60"},
             {"file": "OrderMapper.xml", "lines": "12-30"}],
  "db_objects": ["t_order", "proc_create_order"],
  "confidence": 0.92,
  "status": "draft | confirmed",
  "edited_by_human": false
}
```

- `params_schema` 采用 **JSON Schema**，直接喂给前端自研表单渲染器——动态测试页的实现基础。

### 3.5 知识库与知识包

- **存储布局**：

```
kb_data/
  metadata.db            # SQLite：下述全部表（Flyway 建表）
  artifacts/<project>/   # 摘要.md、diff快照.patch、LLM输出.json 等文件
  index/<project>/       # Lucene 索引（M4 可加向量文件）
  exports/               # 导出的知识包 zip
```

- **导出/导入**：导出 = 打包 `metadata.db + artifacts + index + 提示词模板 + LLM缓存`（凭据默认**不导出**，需显式勾选且再次加密）；导入 = 解包合并，按项目名/时间戳处理冲突（覆盖或并存）。

### 3.6 变更检测与影响分析

- **检测**：`RepoClient` 抽象 + 两个实现——`GitRepoClient`（JGit：fetch + `log <last>..<HEAD>`，M0 PoC-D 已验证）与 `SvnRepoClient`（SVNKit：`svn update` + `log -r <last>:HEAD`，M2 实现）。定时任务（默认 5 分钟）按仓库路由调用；每次同步到的**更新点（提交/版本）全部入库且不可覆盖**，重复同步幂等（按 revision 去重）。
- **改动分类**（决定测试模式建议）：

| 分类 | 判定依据（文件映射，非 LLM 猜测） | 默认建议 |
|------|------|---------|
| SQL 类 | 改动文件映射到 mapper XML / SQL / 存储过程 | **DB 直测** |
| 接口逻辑类 | 映射到 Controller/Service 且不涉及 SQL 签名变化 | HTTP 远程测 |
| DDL 类 | 映射到建表/改表脚本 | DB 直测（需确认提交） |
| 前端类 | 映射到前端目录 | 生成改动摘要，测试走 HTTP 远程测相关接口 |
| 配置/其他 | 无法映射 | 仅摘要，人工判断 |

- **影响分析**：`file → line → ExtractedUnit → 接口/数据对象` 的映射关系在学习阶段持久化，变更时查表得出受影响集合，标注置信度（映射覆盖率高=高，来自 LLM 通读兜底=中）。
- **测试状态标记**（人工驱动，不强制全测）：每条文件级改动带 `test_status: untested | partial | tested | skipped`，可在改动流页面手工标记或由执行结果自动更新（有成功执行记录→已测）；改动流支持按状态过滤，未测项默认醒目展示。

### 3.7 用例生成器

- **输入**：接口卡（含 params_schema）+ diff 上下文 + 关联知识（表结构、已有用例）。
- **输出**：候选用例列表，每条 = `{名称, 场景说明, 参数值, 期望(可人工补充), 模式建议}`。
- **生成策略**：正常路径 1 条 + 边界/异常 2~3 条 + 与 diff 相关的定向用例；**先检索已有用例库，命中相似场景推荐复用**。
- **离线模板**：常用参数模板（空值/极值/超长串/特殊字符/分页边界）内置于系统文件，LLM 不可用时仍可生成基础用例。

### 3.8 执行引擎

#### 3.8.1 HTTP 执行器

- 组装请求：method/path/参数按接口卡渲染，支持 `{{env_var}}` 占位符（base_url、token 等）。
- 执行前经**认证管理**获取会话（见 3.9）。
- 记录：请求/响应快照、状态码、耗时、断言结果；响应预览支持 JSON 折叠与高亮。

#### 3.8.2 DB 执行器（免启动直测，能力 3 的落点）

- 连接：按环境配置的连接串（加密存储），JDBC 连接池复用。
- 执行模型：
  - SQL 模板 + 参数 → **一律 JDBC PreparedStatement 参数绑定**（占位符按方言生成），系统任何 SQL 都不允许字符串拼接/格式化组装——这是硬性编码规约；
  - 默认 `setAutoCommit(false)` → 执行 → 返回结果集/影响行数 → `rollback()`；
  - 需要提交的（DDL 验证等）：页面显式勾选"提交"，走二次确认 + 审计日志；
  - 保护项：超时（默认 10s，`Statement.setQueryTimeout`）、返回行数上限（默认 500 行）、语句黑名单（DROP/TRUNCATE/GRANT 等，可配置）；
  - 存储过程：按数据对象卡的签名生成 `{call ...}` 与出参注册（`CallableStatement`）。
- SQL 模板来源：mapper XML 解析还原（`#{param}` 统一转为安全绑定参数，`${}` 拼接型占位标红提示风险）。

#### 3.8.3 Mock 回放器（二期）

- 测试通过时可选录制 `{请求指纹 → 响应}`；后续同接口可回放，用于离线验证请求构造与参数合法性。

### 3.9 认证与会话管理

- **登录流（LoginFlow）**：学习阶段提取 + 页面可编辑，结构为步骤序列：

```json
{
  "name": "后台管理默认登录",
  "steps": [
    {"action": "http", "method": "POST", "path": "/api/login",
     "body": {"username": "{{cred.username}}", "password": "{{cred.password}}"},
     "extract": {"token": "$.data.accessToken"}}
  ],
  "apply": {"header": {"Authorization": "Bearer {{token}}"}}
}
```

- 会话缓存与过期重登；验证码：步骤标记 `captcha: manual`，执行时弹窗人工输入一次，会话内复用。
- 凭据引用凭据保险库（AES-GCM 加密，主口令启动时解锁或环境变量注入）。

### 3.10 前端动态测试页

- 表单由 `params_schema` 经**自研递归表单渲染器**（Vue3 + Element Plus）自动生成：类型控件、必填校验、枚举下拉、默认值；支持原始 JSON 编辑模式切换。渲染器一期约数百行、无重型依赖，覆盖 string/number/boolean/enum/array/object 即可满足接口测试场景。
- 页面顶部三段式：**环境选择（含模式建议）→ 参数表单 → 执行与结果**；结果区展示响应体、断言、耗时、历史执行对比。
- 接口卡与登录流本身也提供编辑页（表单 + JSON 双模式）。

## 4. 核心数据模型（主要表）

| 表 | 关键字段 | 说明 |
|----|---------|------|
| `projects` | id, name, desc | 项目 |
| `repos` | project_id, vcs_type(git/svn), repo_type(frontend/backend/database), url(远程，可空), local_path, branch, vcs_revision, last_synced_at, watch_enabled | 仓库条目 |
| `commits` | repo_id, revision(git sha/svn r123), author, message, committed_at, processed | 更新点留痕（不可覆盖，revision 去重） |
| `file_changes` | commit_id, path, change_type, patch_file, summary, risk_level, **test_status(untested/partial/tested/skipped)**, tested_at, tested_by | 文件级改动 + 测试标记 |
| `interfaces` | project_id, protocol, name, method, path, params_schema(json), auth, source_map(json), confidence, status, human_edited | 接口卡 |
| `db_objects` | project_id, db_type, obj_type(table/view/procedure/function), name, signature(json), sql_template | 数据对象卡 |
| `login_flows` | project_id, name, steps(json), apply(json) | 登录流 |
| `test_cases` | interface_id 或 db_object_id, name, scenario, params(json), expect, origin(llm/template/human), enabled | 用例 |
| `test_runs` | case_id, mode(http/db/mock), env_id, commit_id(关联触发改动), request_snapshot, response_snapshot, status, latency_ms, executed_by, executed_at | 执行记录 |
| `environments` | project_id, name, base_url, db_conn_enc, vars(json) | 测试环境 |
| `credentials` | name, cipher_text, kind | 凭据保险库 |
| `llm_providers` | name, base_url, api_key_enc, model, purpose_routing(json), enabled, is_default | LLM 配置 |
| `llm_cache` | fingerprint, response, model, created_at | LLM 缓存 |
| `tasks` | type, payload, status, retry_count, last_error | 后台任务表（单实例单写者） |
| `audit_logs` | actor, action, target, detail, at | 审计 |
| `file_bindings` | repo_id, file, line_start, line_end, unit_kind, unit_id | **文件↔实体映射（影响分析的基石）** |

系统自身元数据一律通过 Spring JDBC 访问，外部输入全部 PreparedStatement 参数绑定（编码规约 + Code Review 检查项）。

## 5. 关键流程

### 5.1 首次全量学习

```
注册项目/仓库 → 后台任务：目录扫描 → 适配器抽取(产出ExtractedUnit)
→ 聚合分组 → LLM提炼接口卡/摘要(草稿) → Lucene索引
→ 用户在"知识确认"页逐条确认 → 状态confirmed → 可发起测试
```

### 5.2 增量：提交 → 归纳 → 用例

```
JGit轮询发现新commit → 解析diff存快照 → 逐文件查file_bindings分类
→ 受影响实体集合 → LLM生成改动摘要+风险等级(缓存优先)
→ 增量更新受影响实体知识(保护人工编辑字段) → 生成候选用例
→ 改动流页面呈现卡片(摘要/影响面/用例入口) → 通知(M5)
```

### 5.3 DB 直测

```
选择SQL类改动/数据对象 → 动态表单填参(或用例带入)
→ DB执行器: 取连接 → setAutoCommit(false) → PreparedStatement参数绑定执行
→ 结果截断返回 → rollback() → 记录test_runs → 审计
```

### 5.4 HTTP 远程测（自动登录）

```
选择环境 → 会话不存在/过期? → 执行登录流(验证码则人工输入) → 缓存会话
→ 渲染请求(注入鉴权头) → 发送 → 断言 → 记录结果
```

### 5.5 离线迁移


## 7. 安全设计

1. **系统自身数据访问**：Spring JDBC 全 PreparedStatement 参数绑定，禁止拼接/格式化组装 SQL（编码规约 + Code Review 检查项）。
2. **直测目标库**：
   - 连接账号建议只读或独立测试账号；页面保存连接时提供"连通性 + 权限体检"；
   - 默认事务回滚、提交需显式勾选 + 二次确认；语句黑名单、超时、行数上限可配置；
   - `${}` 拼接型 SQL 占位强制标红提示。
3. **凭据与密钥**：AES-GCM 加密落盘；主口令来自环境变量或启动输入，不入库；LLM Key 同样加密。导出知识包默认剔除凭据。
4. **审计**：登录、配置变更、测试执行、导出导入全量留痕。
5. **代码外发**：云端 LLM 调用前提示"代码片段将发送至 xxx"；设置页可一键切换本地模型供应商；涉密项目可标记 `llm_forbidden` 强制降级模式。
6. **传输**：默认监听内网地址；支持反向代理挂 HTTPS。

## 8. 部署形态（非 Docker，自包含部署包）

### 8.1 部署包结构（解压即用）

```
preflight/                       # 部署根目录（拷贝到服务器任意位置）
├── jre/                         # 便携 JRE（Temurin 21，随包分发，目标机无需装 Java）
├── lib/preflight-server.jar     # 单体 fat jar（内含前端静态资源）
├── config/application.yml       # 端口、知识库路径、主口令来源等配置
├── data/                        # kb_data（SQLite/文件/索引）——升级不动这里
├── logs/
└── bin/                         # start.sh / stop.sh / restart.sh / status.sh + Windows .bat
```

### 8.2 启停脚本（正式交付物：M0 随脚手架落地，M5 随部署包收口）

Linux `bin/start.sh` 示例（**仅在脚本进程内设置 JAVA_HOME，不改系统环境**）：

```sh
#!/bin/sh
APP_DIR=$(cd "$(dirname "$0")/.." && pwd)
JAVA="$APP_DIR/jre/bin/java"
nohup "$JAVA" -Xms512m -Xmx2g -jar "$APP_DIR/lib/preflight-server.jar" \
  --spring.config.additional-location="file:$APP_DIR/config/" \
  > "$APP_DIR/logs/stdout.log" 2>&1 &
echo $! > "$APP_DIR/preflight.pid"
```

- `stop.sh`：按 pid 文件发 SIGTERM 优雅停机，超时后升级处理；
- `status.sh`：检查进程 + 健康接口 `/actuator/health`；
- `restart.sh`：组合调用；
- Windows 开发机提供 `start.bat / stop.bat / status.bat`（路径与端口只在 `dev\bin\_env.bat` 里有一份；java 次序 `dev\jre\` → `tools\jdk-*` → PATH，同样不改环境变量，认进程按端口不按进程名）。

### 8.3 形态与升级

- 单机单进程，默认端口 8320（config 可改）；内网任意目录解压即用，**无需 root、无需预装任何组件、不使用 Docker**。
- 升级 = 停服 → 备份 `data/` → 替换 jar → 起服；数据全在 `data/`，与版本无关。
- **《部署运维手册》（安装、启停、升级、备份恢复、常见问题）为正式交付物（M5）**。
