## 1. 人力假设与总体节奏

- 建议配置：**后端 1~2 人（其中 1 人牵头）+ 前端 1 人（可由后端兼任；动态表单为自研递归渲染器，工作量可控）**。
- 工具链：统一使用 `tools/` 内 JDK 21（Temurin 21.0.12）+ Maven 3.9.11（华为云镜像），脚本内进程级指定 `JAVA_HOME`，**不改动开发机既有 JDK 1.8 环境与任何系统变量**（已验证可用）。
- 总体周期：**约 12~13 周到 M5 全量**；**M1+M2 共 6 周形成 MVP**，即可开始在实际项目中试用并收集反馈。
- 节奏原则：每个里程碑结束有一次"真项目试用"，用真实仓库校准解析器与提示词，避免闭门造车。

## 3. 各期详细范围与验收标准

### M0 · 技术验证（0.5 周）

**任务**：
1. 工程脚手架：Spring Boot 单体（REST + Vue3 静态资源内嵌 + 定时任务）+ SQLite/Flyway + **Windows/Linux 启停脚本（bat/sh：脚本内指定 `tools/` 内 JDK，进程级 JAVA_HOME，不改系统环境）**。
2. PoC-A：LLM 网关——OpenAI 兼容 + Ollama 两种供应商各打通一次调用，缓存与重试逻辑成型。
3. PoC-B：解析——JavaParser 解析一个样例 Spring Boot 项目的 Controller，DOM 解析 mapper XML 并用 JSqlParser 还原校验 SQL，产出 ExtractedUnit。
4. PoC-C：DB 直测——JDBC PreparedStatement 执行参数绑定查询 + 事务回滚，验证"测完无痕"。

**验收**：三个 PoC 现场演示通过；启停脚本在本机（不改环境变量）与一台干净 Linux 机器上各验证一次起停正常。

### M1 · 学习闭环（3 周）

**任务**：
1. 项目/仓库管理（类型化目录、分支、排除规则）。
2. 扫描引擎框架 + **Java/Spring + MyBatis 适配器（JavaParser）** + **SQL 适配器（JSqlParser + JDBC 元数据）**。
3. LLM 提取流水线（聚合分组 → 接口卡/摘要 → 草稿入库）与提示词模板管理。
4. 知识库建表（Flyway）、artifacts 文件存储、file_bindings 映射写入、Lucene 检索（BM25）。
5. 前端：项目页、学习进度（SSE）、知识确认页（草稿列表 + 编辑 + 批量确认）、LLM 配置页（多供应商 + 用途路由 + 连通性测试）。

**验收标准**：
- 接入一个真实后台项目（≥30 个接口），2 小时内完成学习，接口卡字段抽取准确率 ≥85%（人工抽检 20 条），确认后可浏览完整接口清单；
- LLM 配置页可配置 ≥2 个供应商并指定"摘要用 A、生成用 B"。

### M2 · 测试闭环（3 周）

**任务**：
1. 基于 RepoClient 抽象的变更检测：**GitRepoClient（JGit，M0 PoC-D 已验证）+ SvnRepoClient（SVNKit）**，定时自动拉取（git fetch / svn update），更新点留痕入库（幂等）、commit/diff 落库、改动分类（查 file_bindings）。
2. 改动摘要生成（LLM + 缓存）、影响接口清单。
3. 用例生成器（增量：只对受影响实体生成，含已有用例复用推荐）。
4. 动态测试页（JSON Schema → 自研递归表单渲染器、原始 JSON 模式、执行结果区）。
5. HTTP 执行器 + 登录流管理（步骤编辑、会话缓存、Token 注入、验证码人工兜底）。
6. 环境管理页（多环境 base_url/变量）。
7. **已测/未测标记**：改动流页面标记（untested/partial/tested/skipped）+ 状态过滤 + 执行结果自动回写标记。

**验收标准**：
- 提交一组改动（改 1 个 Controller + 1 个 mapper），10 分钟内改动流出现卡片：摘要可读、影响接口正确命中、自动生成 ≥3 条用例；
- 对同一个 Git 仓库和同一个 SVN 仓库各完成一次"自动拉取 → 更新点留痕 → 重复同步幂等（newRecorded=0）"验证；
- 在动态测试页对被测服务完成一次"自动登录 → 选环境 → 填参 → 执行 → 看到响应与断言"全流程，全程不离开页面；
- 改动流中未测项有醒目标识，可手工标记"已测/部分测/跳过"且被正确过滤。

*M1+M2 结束 = MVP 上线，投入真实试用。*

### M3 · 免启动直测（2 周）

**任务**：
1. DB 执行器：连接管理、参数绑定（硬规约）、事务回滚、超时/行数/黑名单保护、提交二次确认。
2. mapper XML/注解 SQL → 可执行 SQL 模板还原（`#{}` 绑定、`${}` 标红）；存储过程签名提取与 CALL。
3. "SQL 类改动"直测链路：改动卡片 → 直测表单 → 执行 → 结果。
4. 凭据保险库（AES-GCM、主口令）、连接权限体检。

**验收标准**：
- 改一条 mapper SQL 后**不启动后台服务**，完成填参 → 执行 → 查看结果，且库中数据零残留（回滚验证）；
- 对一个含出入参的存储过程完成直测；
- 黑名单语句（如 DROP TABLE）被拦截并留审计。

### M4 · 离线与迁移（2 周）

**任务**：
1. 知识包导出/导入（含冲突处理、凭据默认剔除）。
2. 本地 embedding 模型接入（DJL + ONNX Runtime 运行 bge-small-zh，模型文件随包分发，纯本地推理）与向量检索离线化。
3. 模板化离线用例（内置参数模板生成器）。
4. LLM 缓存命中链路收口；`llm_forbidden` 降级模式（结构化 diff 报告替代 LLM 摘要）。

**验收标准**：
- 在一台断网机器上导入知识包后：接口清单、动态测试页、HTTP 远程测、DB 直测、模板用例全部可用；改动摘要以降级形式产出；
- 导出→导入往返无知识丢失（用例数、接口数对账）。

### M5 · 加固与增值（2 周）

**任务**：
1. 改动风险分级与改动流置顶提醒。
2. 测试报告（单次改动报告 + 项目周期报告，可导出）。
3. 审计日志页面、系统操作留痕收口。
4. 质量看板基础版（按人/项目：提交数、改动是否测试、发现问题数）。
5. 通知集成（企业微信/钉钉机器人：新改动卡片 + 测试结果摘要）。
6. **启停脚本收口（Linux sh + Windows bat）、便携 JRE 离线部署包、《部署运维手册》（安装/启停/升级/备份恢复）、使用手册**。

**验收标准**：
- 全功能回归通过；断网环境 + 云端环境两套部署各演练一次；
- 按使用者角色（测试员/开发/管理员）各走一遍手册场景。

## 4. MVP 裁剪建议

若资源紧张或希望更早见效，**保底范围 = M1 + M2 + M3 中的"mapper SQL 直测"子集**：

- 可延后：Mock 回放、看板、通知、多环境、团队共用（PostgreSQL）、Node/Python 适配器（先只覆盖 Java + SQL 主栈）。
- 不可裁剪：知识落盘结构（M1 就要按"可迁移"设计，事后补代价大）、参数绑定规约、草稿确认工作流。

## 5. 风险与对策

| 风险 | 影响 | 对策 | 责任期 |
|------|------|------|--------|
| LLM 抽取不准确/幻觉 | 知识库错误，误导测试 | 草稿确认工作流 + 置信度 + 静态解析打底（LLM 只做归纳不做唯一定位）+ 人工可编辑且编辑优先 | M1 起持续 |
| 超大仓库学习慢 | 首次接入体验差 | 增量索引、glob 排除、分批学习、文件哈希跳过 | M1 |
| 目标库直测安全 | 污染/破坏数据 | 只读账号建议 + 默认回滚 + 黑名单 + 提交二次确认 + 审计 | M3 |
| 特殊登录（验证码/SSO） | 自动登录受阻 | 人工兜底输入一次、会话复用、Cookie 接管；实施前调研目标系统登录方式 | M2 |
| 框架差异大，适配器工作量 | 进度延期 | 适配器接口先行稳定；一期只承诺 Java+MyBatis+SQL；其余走 LLM 通读兜底 | M1~M3 |
| 云端 LLM 合规（代码外发） | 无法用云模型 | 本地 Ollama/vLLM 支持 + `llm_forbidden` 标记 + 离线降级 | M4 |
| SQLite 并发写冲突 | 偶发锁表 | 后台任务单写者队列；预留 PostgreSQL 切换 | M1 设计预留 |
| 开发/运行环境 JDK 冲突 | 构建失败或污染用户环境 | 全程使用 `tools/` 内 JDK 21 与 Maven，脚本与构建命令**进程级**指定 JAVA_HOME，不写系统环境变量；部署包自带便携 JRE，目标机零安装 | M0 |

## 6. 上线后的成功度量（建议）

1. **改动覆盖率**：被系统感知的提交中，完成过至少一次测试的改动占比（目标 ≥70%）。
2. **拦截率**：测试阶段发现问题数 / 上线后回溯与改动相关的问题数（先建立记录习惯，3 个月后定基线）。
3. **直测占比**：SQL 类改动中免启动直测完成率（体现能力 3 的价值，目标 ≥80%）。
4. **用例复用率**：执行用例中来自资产库的比例（反映知识沉淀效果）。
