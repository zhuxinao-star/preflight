# PreFlight · 实现审查与返工清单

> 版本：v1.0
> 日期：2026-09-19
> 审查对象：`preflight/preflight-server/`（40 个 Java 文件约 5,360 行；Flyway V1~V8；前端 `resources/static/` 原生 JS 833 行）
> 审查依据：《01-解决方案》《02-概要设计》《03-开发计划》《04-补齐与亮点设计》（冲突以 04 为准）
> 审查方法：双路逐模块代码比对（学习/变更侧 + 执行/平台侧）＋ 审查人独立复核关键论断 ＋ 实际构建与单测
> 本文不修改任何代码；§9 为可直接投喂开发工具的返工清单

## 1. 总体结论

**这是一个"骨架忠实、深度六成、闸门最薄"的实现。** 18 张表数据模型齐全、八页面齐备、04 新增项多数落了地，方向没有跑偏；但：

- 学习/变更侧完成度约 **55~60%**，执行/平台侧约 **62%**；
- 三个**阻断级缺陷**使系统两大卖点当前实际不可用：自动登录链路（能力 4）100% 失败、影响分析基石（file_bindings）在真实多模块仓库会大面积错绑/漏绑；
- 04 文档反复强调的三道保命闸门（DDL 提交闸门、RBAC、直测参数绑定规约）**恰恰是实现最薄处**——尤其 DDL 闸门条件写反，不勾"提交"的 DDL 照样永久落库且 UI 谎报"已回滚（无痕）"；
- 结论：**不可直接进入真实项目试用**；按 §8 三批次返工后再启动 dogfooding。

## 3. P0 —— 阻断与安全（返工第一优先）

### R1 DDL 提交闸门条件写反 + UI 谎报回滚 ⚠最严重
- 证据：`exec/DbExecutorService.java:80-95`（`:83` 闸门仅当 `allowCommit=true` 才判断；`:95` `setAutoCommit(isDdl || allowCommit)` 使未勾提交的 CREATE/ALTER 在隐式提交库直接永久落库）；`static/app.js:464`（`committed=false` 一律显示"已回滚（无痕）"）。
- 危害：击穿 04 §3.1"防一次直测毁掉一套库"第一道闸；且结果反馈造假。
- 返工：DDL 且不可回滚库且环境未标可弃 → 一律拒绝执行；提交通道仅 admin（见 R4）；返回值如实携带 `ddlAutoCommitted` 并在前端红字展示"DDL 无法回滚，已永久生效"。
- 验收：viewer/tester/admin 三角色 × 勾/不勾提交 × DDL/DML × 可回滚/不可回滚库矩阵全测，UI 展示与实际库状态一致（用 `sp_executesql` 后再查系统表验证残留为零）。

### R2 自动登录链路实际不可用（能力 4 主链路）
- 证据：前端 steps/apply 以字符串提交（`static/app.js:719-720`），后端 `toJson` 再编码双重落库（`exec/TestController.java:275-276`）；执行侧 `readValue(...,List.class)` 必抛。另：`cred_id` 取出从未使用（`HttpExecutorService.java:170` 死代码）、`{{cred.*}}` 全库无实现、无会话缓存/过期重登（每次 run 重登 `:88-94`）、`captcha: manual` 零实现、无 Set-Cookie 接管。
- 危害：所有"登录流+Token 注入"的 HTTP 测试 100% 失败；验证码/SSO 兜底（01 §3 能力4）不存在。
- 返工：修编码（前端发对象、后端直接序列化一次）；凭据引用在登录步骤内生效；会话按 环境+登录流 缓存至过期并自动重登；`captcha: manual` 弹窗人工输入一次会话内复用；Cookie 接管（存/复用 Set-Cookie）。
- 验收：UI 配置一条登录流 → 带鉴权接口执行成功；会话有效期内第二次执行不再调登录接口；人工验证码兜底可走通。

### R3 影响分析基石错绑（全系统唯一"确定性"卖点）
- 证据：`learn/LearnService.java:66,72,102,252-256` file_bindings 以**文件名**为 key 反查相对路径——同名文件跨目录串绑；绑定根=学习目录而 `file_changes.path`=VCS 根相对——子模块学习必漏；`ai/ImpactService.java:34-35` 用 `LIKE '%'+path` 后缀匹配——误配且无法走索引。
- 返工：绑定键改**仓库根相对全路径**；diff 路径与绑定路径同一根基准（记录 repo 内相对根）；LIKE 改等值查询；补"未映射文件"兜底展示（01 能力2：无法映射→仅摘要人工判断，当前无此分类）。
- 验收：构造 `module-a/OrderMapper.xml` 与 `module-b/OrderMapper.xml` 同名场景，改动各自只命中本模块接口；子目录学习后改动可命中。

### R4 RBAC 只有"admin 写前缀黑名单"一层
- 证据：`common/AuthInterceptor.java:20-23,46-59`——`/api/db-test`、`/api/test-runs`、`/api/interfaces/confirm`、`/api/changes/*/test-status` 均不在名单 → **viewer 可执行测试、可直测、可确认知识**；`/api/auth/**` 整体放行（`:35`）导致未登录可 `GET /api/auth/users` 列用户（`AuthController.java:92-96`）；pre/post 钩子以 `allowCommit=true` 显式提交通道执行（`TestRunService.java:77-108`）却无角色校验无审计（`TestController.java:137-146`），绕开提交限制；`tested_by` 前端自报（`ChangeController.java:203`）。
- 返工：按 04 §3.6 权限矩阵逐路由声明（建议注解式）；钩子执行入审计；actor 一律取会话。
- 验收：三角色 × 全敏感路由 403/通过 矩阵测试；审计中 actor 不可伪造。

### R5 知识包导入 Zip Slip 路径穿越
- 证据：`system/ExportService.java:102-107` 拼接 entry 名落盘无 `normalize().startsWith(target)` 校验。
- 返工：路径校验 + 拒绝绝对路径/`..` 条目；知识包格式补 §3.1 "metadata.db + 提示词模板 + LLM 缓存"（现仅 manifest.json 全表 JSON + artifacts，提示词与缓存未随包迁移，违背 01 能力 6 与 02 §3.5）。

### R6 L4 回读断言 SQL 字符串替换（注入面，违"全绑定"硬规约）
- 证据：`exec/AssertionEngine.java:55-56` `substitute(expr, ctx.body())` 后以空参数列表执行——值直接拼进 SQL。同类违规：`exec/TestController.java:171-175` 拼接查询（靠去引号过滤）。
- 返工：改模板 + 绑定参数（`{{ret.x}}` 解析为占位 `?` 入参列表）；把"系统任何 SQL 不得字符串拼接"列为 Code Review 检查项并加 ArchUnit/正则扫描兜底。

### R7 MySQL/TiDB 无驱动
- 证据：pom 依赖清单（§2 实测）。D2 六库矩阵中两库直测必失败。
- 返工：`com.mysql:mysql-connector-j` 入 pom（华为云镜像可取）；TiDB 复用之并验证 `SELECT VERSION()` 识别。

### R8 直测存储过程无出参
- 证据：`exec/DbExecutorService.java:101-115` 仅 `setObject`，无 `registerOutParameter`、无超时；01 能力3/02 §3.8.2 明确承诺出入参。
- 返工：按数据对象卡签名注册 OUT/INOUT（`CallableStatement`），出参回显进结果区与断言上下文；补 `setQueryTimeout`。
- 验收：DM8 与 MySQL 各对一个含 IN/OUT 的 proc 直测成功并展示返回值。
